# 随机事件设计

对应 Task.md 第 8 项。地图上的 `event` 节点（权重 22，最常见的非战斗房间）目前走占位界面，本设计让它变成真正的事件。

## 目标

- 8 个类别各 2 个事件，共 16 个，每个事件都是"有取舍的选择"，没有纯白送的选项。
- 事件由种子决定：同一种子、同一节点，永远抽到同一个事件。
- 事件内容是数据，新增事件不改引擎。

## 非目标

- 不做多层嵌套的剧情分支（每个事件最多"选择 → 结果"两步）。
- 不做事件专属美术，沿用现有 emoji 图标与暗色场景风格。
- 商店（第 9 项）不在本设计内。

## 数值基准

玩家最大生命 80，金币收入约 30 / 90 / 150（普通 / 精英 / Boss），休息回复 24。
事件的生命代价取 6–15（约 8%–19%），金币代价 40–75，让"花钱、掉血、吃诅咒"三种代价都有分量，但不致命。
生命代价不会把玩家打死：扣血最多扣到 1 点；生命不足以支付时，该选项置灰。

## 抽取规则

1. 抽取随机流：`deriveSeed(seed, 'event:' + 节点id)`。
2. 候选 = 全部事件，去掉本局已出现过的（`run.seenEvents`），再去掉前置条件不满足的（如"牌组里没有可升级的牌"）。
3. 候选里等概率抽一个。候选为空（16 个全见过）时，清空 `seenEvents` 重新开始。
4. 每个事件有 `weight`（默认 1）。战斗类事件和诅咒类事件权重取 0.7，让它们略少于安全事件。

## 结果原语

事件的每个选项由若干"结果"组成，结果只用下面这些原语，引擎实现一次即可：

| 原语 | 含义 |
|------|------|
| `gold ±n` | 增减金币（不会减到负数） |
| `hp ±n` | 增减当前生命（下限 1，上限最大生命） |
| `maxHp ±n` | 增减最大生命，当前生命同步变化 |
| `relic` | 获得一个随机未拥有遗物（走现有 `acquireRelic`） |
| `potion n` | 获得 n 瓶随机药水，栏位满则多余的丢弃 |
| `addCard id` | 往牌组加入指定卡牌（诅咒牌、增益诅咒牌） |
| `removeCard` | 进入选牌界面，删除选中的一张牌 |
| `upgradeCard` | 进入选牌界面，升级选中的一张牌（复用锻造界面） |
| `upgradeRandom n` | 随机升级 n 张未升级的牌 |
| `battle kind` | 进入战斗（`monster` / `elite`），战斗胜利后照常出奖励 |
| `chance p, 成功结果, 失败结果` | 概率结果；概率由事件随机流决定，所以可复现 |

选项还可以带：
- `cost`：`{ gold?: n, hp?: n }`，不足时置灰并显示原因。
- `requires`：额外前置条件（如"有未升级的攻击牌"），不满足时置灰。

## 新增卡牌

现有引擎没有"打不出去的牌"和"自损的牌"，需要新增：

### 引擎能力（最小集）

- `CardDef.unplayable?: boolean`：不能打出。手牌界面置灰，`playCard` 返回 `invalidAction`。
- `Effect` 新增 `{ type: 'loseHp'; amount: number }`：玩家失去生命（不被格挡抵消）。
- `CardDef.rarity` 增加 `'curse'`：诅咒牌，不进入奖励池，不出现在初始牌组。
- 回合结束钩子：手牌里的牌可声明 `onTurnEndInHand` 效果（只用于灼伤）。

### 诅咒牌（2 张）

| id | 名称 | 效果 |
|----|------|------|
| `wound` | 伤口 | 不能打出，占手牌位 |
| `burn` | 灼伤 | 不能打出；回合结束时若在手牌中，失去 2 点生命 |

### 增益诅咒牌（2 张，带代价的强牌，可以打出）

| id | 名称 | 费用 | 效果 | 升级后 |
|----|------|------|------|--------|
| `bloodPact` | 血之契约 | 0 | 失去 4 点生命，造成 18 点伤害 | 造成 24 点伤害 |
| `frenzy` | 狂乱 | 0 | 失去 5 点生命，获得 2 点能量，抽 2 张牌，消耗 | 抽 3 张牌 |

增益诅咒牌的稀有度为 `gold`，但不进奖励池，只能从事件获得。

## 事件清单

### 一、删除事件

**遗忘之泉** 🌊
> 泉水清澈得不真实。有人说喝下去，就能忘掉一些不想要的东西。
- 饮水：失去 8 点生命，删除一张牌。
- 离开。

**流浪裁缝** 🧵
> 裁缝抖开一块布："你的行囊太满了，我替你剪掉一点。"
- 付 75 金：删除一张牌。
- 免费修补：删除一张牌，并获得一张【伤口】。
- 离开。
- 前置：金币选项需要 ≥ 75 金。

### 二、升级事件

**老铁匠** 🔨
> 一间没人看管的铁匠铺，炉子还是热的。
- 亲手锻打：失去 6 点生命，升级一张牌。
- 借用炉火：随机升级 2 张牌，获得一张【灼伤】。
- 离开。
- 前置：牌组里有 ≥ 2 张未升级的牌。

**磨刀的旅人** 🪨
> 旅人蹲在路边磨刀，抬头看你的武器："给你也磨磨？"
- 付 40 金：升级一张牌。
- 请他随手磨：随机升级 1 张牌，最大生命 -5。
- 离开。
- 前置：牌组里有未升级的牌。

### 三、遗物事件

**神秘祭坛** ⛩️
> 祭坛上刻着凹槽，像是在等待供奉。
- 供奉 50 金：获得一件遗物。
- 献血：失去 15 点生命，获得一件遗物。
- 离开。

**破旧宝箱** 🧰
> 箱子的锁已经锈断，但里面有东西在动。
- 打开：50% 获得一件遗物；50% 获得【伤口】并失去 8 点生命。
- 离开。

### 四、诅咒事件

**恶魔的契约** 😈
> "给你力量，"低语说，"只收一点点代价。"
- 签下契约：获得一件遗物，获得两张【伤口】。
- 拒绝：恢复 10 点生命。

**低语的石像** 🗿
> 石像的嘴里吐出金币，眼睛却一直盯着你。
- 拿走金币：获得 200 金，获得一张【灼伤】。
- 只拿一半：获得 90 金。
- 离开。

### 五、金钱事件

**路边赌徒** 🎲
> "押多少？赢了翻倍，输了归我。"
- 押 50 金：50% 获得 100 金（净赚 50）；50% 失去押金。
- 押 100 金：45% 获得 220 金（净赚 120）；55% 失去押金。
- 离开。
- 前置：对应金币选项需要足够的金币。

**倒下的商人** 🐪
> 商人倒在路边，货车翻了，他还有一口气。
- 救助：失去 10 点生命，获得 1 瓶药水，获得 60 金（他的谢礼）。
- 搜刮：获得 120 金；40% 引来强盗，进入一场普通战斗。
- 离开。

### 六、战斗事件

**埋伏** ⚔️
> 林子里的动静不对，你已经被围住了。
- 迎战：进入一场普通战斗，胜利后额外获得 40 金。
- 破财消灾：付 50 金，直接离开。
- 前置：金币选项需要 ≥ 50 金。

**怪物巢穴** 🕳️
> 洞口散落着骨头，深处闪着光。
- 闯入：进入一场精英战斗，胜利后额外获得一件遗物（精英本身的掉落照常）。
- 离开。

### 七、诅咒增益卡事件

**血色祭坛** 🩸
> 祭坛上浮着一张卡牌，边缘还在滴血。
- 取走：获得【血之契约】。
- 离开。

**狂乱符文** 🌀
> 墙上的符文在移动，看久了头会疼。
- 抄下符文：获得【狂乱】，获得一张【灼伤】。
- 离开。

### 八、药水事件

**游方药剂师** ⚗️
> 药剂师摊开一排瓶子："随便拿一瓶，当交个朋友。"
- 随机拿一瓶：获得 1 瓶药水。
- 付 40 金：获得 2 瓶药水。
- 离开。

**毒雾沼泽** ☣️
> 沼泽边长着发光的草药，空气让你喉咙发紧。
- 深入采集：失去 10 点生命，获得 2 瓶药水。
- 在外围采集：获得 1 瓶药水。

## 流程与数据结构

### 数据（`data/events.ts`）

```ts
interface EventDef {
  id: string
  title: string
  icon: string
  text: string
  weight?: number
  /** 事件是否可出现（如牌组里没有可升级的牌就不出） */
  requires?(run: RunState): boolean
  options: EventOption[]
}
interface EventOption {
  label: string
  cost?: { gold?: number; hp?: number }
  requires?(run: RunState): string | null   // 返回不可选的原因
  outcomes: Outcome[]                        // 见"结果原语"
}
```

### 引擎（`engine/event.ts`，纯 TS）

- `RunScreen` 增加 `'event'`；`RunState` 增加 `event: { id: string; result?: string } | null` 和 `seenEvents: string[]`。
- `RunAction` 增加 `chooseEventOption { index }`；选完后展示一段结果文字，再用现有的 `leave` 回到地图。
- `chooseNode` 遇到 `event` 节点时：按抽取规则选事件，进入 `event` 界面（不再走 `placeholder`）。
- 需要选牌的结果（`removeCard`、`upgradeCard`）进入选牌界面，选完回到事件的结果页。选牌界面复用 `ForgeView`（升级）和 `EnchantView` 的布局，新增一个删除版本。
- `battle` 结果：创建战斗，战斗结束后的奖励里追加事件指定的额外奖励；战斗结束回到地图，不回到事件。
- 引擎仍不依赖 `data` 目录：事件定义和诅咒牌像卡牌、遗物一样，由调用方通过 `RunContent` 注入。

### 界面

- `EventView.vue`：左侧大图标 + 标题 + 描述，右侧竖排选项按钮；不可选项置灰，下方小字写原因（"金币不足"、"没有可升级的牌"）。
- 点选项后，描述区换成结果文字，选项区换成一个"继续"按钮。

## 我替你定的几个点（请确认或改）

- **每类别 2 个事件**：Task.md 没规定数量，我先按每类 2 个出一版。
- **事件不可重复**：同一局内一个事件只出现一次，16 个出完再重来。
- **诅咒牌只有 2 种**，且都是"死牌"思路，没有复杂机制。
- **遗物事件的遗物是随机的**，不让玩家看到是什么再选；这样"赌"的味道更足。
- **所有事件都有"离开"或一个低代价选项**，不会出现被迫吃亏的事件（战斗事件除外，它本来就有逃跑选项）。
- 数值是第一版，没有经过平衡测试。
