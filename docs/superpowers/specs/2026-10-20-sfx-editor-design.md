# 音效编辑面板 设计

## 目的

游戏里大部分动画（史莱姆分裂、出牌、抽牌、敌人行动……）目前没有音效，已有的几个音效（金币、回血、扣血、命中、格挡、锻造、塞入诅咒牌）也是写死在界面代码里的。

做一个**仅开发模式**的"音效编辑"面板，操作方式参照现有的卡牌编辑面板：

1. 左侧列出游戏里"会发生的事"（音效槽位），标明哪些还没配音效。
2. 选中一个槽位，右侧**原样复现**对应的游戏场景和动画，并同时播放当前音效。
3. 用户从音效库里挑文件（或导入新文件），试听并和动画一起重播。
4. 满意就点保存：音效文件进入项目，槽位与文件的对应关系写回源码，游戏里立刻生效。不保存则什么都不变。

**核心价值：** 以后所有动作都需要音效，用户亲自挑，并且能看着真实动画挑。新增一种动作时，只要登记一个槽位，面板里就自动多出一行。

## 现状（以代码为准）

- 触发点全部写死在界面代码里，共 8 处左右：`BattleView`（格挡、受伤 / 命中、回血、史莱姆分裂）、`RunHud`（金币）、`RelicReveal`（锻造、附魔）、`RunView`（诅咒 / 普通塞牌）。
- `useSfx.ts` 里用文件名 `名字-序号.ogg` 通过 glob 自动分组；`enchant-1.mp3` 是 mp3。
- 史莱姆分裂音（`playSplitSfx`）是代码合成的，没有音频文件。
- `playSfx(name, volume, maxSeconds)` 带"只播开头 N 秒"参数，锻造用了 0.5 秒。
- 防爆音节流按音效名，40 ms 内同名只响一次。
- 绝大多数事件（出牌、抽牌、状态、药水、敌人行动、胜负等）目前没有任何触发点。

## 目标

- 覆盖所有有动画 / 有反馈的游戏事件（清单见下）。
- 场景复现与真实游戏**使用同一套表现代码**，不另画一份。
- 一个槽位可挂一个或多个音效，多个时每次随机轮换（与现有行为一致）。
- 保存即写回源码；游戏里所有触发点统一从一份配置表取音效。
- 未配音效的槽位一眼可见。

## 非目标

- 不做某张牌 / 某个敌人 / 某个遗物的专属音效（先做到"每类事件一个槽位，原因不同的拆开"）。后续要细化，可在槽位键上加后缀，不影响本设计。
- 不做背景音乐、界面按钮点击音。
- 不做音频波形编辑、剪裁、混音。
- 不在正式发布的构建里带这个面板和写文件接口。

## 反目标（即使技术上能用也算失败）

- 面板里看到的动画和真实游戏不一致（说明复现是另画的）。
- 保存后需要手动改代码或重启才生效。
- 开发服务器的写文件接口能被其他网页调用。

## 约束

- 技术栈沿用现有：Vue 3 + TS + Vite，界面用 UnoCSS，开发模式下通过 Vite 插件写回源码，与 `tools/cardEditorPlugin.ts` 同构。
- 入口、关闭方式、未保存提示等交互沿用 `CardEditorView.vue` 和 `App.vue` 里现有的开发入口做法。
- 写文件接口需要自定义请求头校验（参照卡牌编辑插件的 `x-card-editor`），且只在 `apply: 'serve'` 时存在。
- 音频用 Web Audio 播放（现有 `src/composables/useSfx.ts`）。
- 项目内音效文件放 `src/assets/sfx/`，格式为 ogg。

## 用户已确定的内容

- 面板形态：左侧选事件，右侧复现场景并发声，选音效、保存、生效。
- 场景复现要有真实场景，不是示意图。
- 当前大多数动画没有任何音效，面板要负责"从无到有"地配。
- 之后所有动作都需要音效。

## 设计（其中标"我的决定"的是我替用户定的，需要核对）

### 1. 音效槽位表（集中配置）

- 新增一份数据文件，例如 `src/data/sfxMap.ts`：槽位键 → 音效文件名数组。由编辑面板的保存接口整体重写，类似卡牌文件的写回方式。
- 新增槽位的定义（键、中文名、分组、复现脚本）放在另一份数据里，作为面板的清单来源；`sfxMap.ts` 只存"用户选了什么"。
- `useSfx.playSfx(slot)` 改为按槽位键从配置表查文件。未配置的槽位静默不播。
- 现有写死的 `playSfx('coin' | 'heal' | …)` 调用迁移到槽位键，并把当前的音效文件作为这些槽位的初始配置，保证迁移后听感不变。
- **我的决定：** 槽位键使用 `分组.事件.变体` 的点分写法，如 `battle.damage.player`。

### 2. 槽位清单（初版，对应引擎的 `GameEvent` 及战斗外反馈）

战斗内：
- 出牌（按牌类型：攻击 / 技能 / 能力）、抽牌、洗牌、获得能量、弃手牌、回合开始、完美格挡
- 受伤：玩家受伤、敌人受伤、毒伤、触发类伤害（如灼伤）、伤害被护盾完全挡住
- 获得护盾：玩家、敌人
- 回血：玩家、敌人
- 状态：增益上身、减益上身、状态移除、状态触发、手牌里的牌触发（灼伤等）、附魔成长
- 塞牌：诅咒 / 状态牌塞入、其他牌塞入
- 药水使用
- 敌人行动：攻击（冲撞）、非攻击行动
- 敌人变化：登场、史莱姆分裂、逃跑
- 金币：被偷、被还回
- 战斗结束：胜利、失败

战斗外：
- 金币增加、金币减少、商店买不起、锻造升级、获得遗物、战斗外失血

**我的决定：** 清单以上面为准，面板里没有槽位的事件视为没有音效；新增事件时登记槽位即可。

### 3. 场景复现

- 每个槽位定义一段**复现脚本**：一份预设的战斗状态加一串 `GameEvent`，通过现有的演出队列（`pushFx` / `enqueueFx`）放进真实的 `BattleView`，由真实代码演动画并触发音效。
- 战斗外槽位（商店、锻造、金币变化、塞牌、获得遗物）复现用对应的真实界面组件或其最小承载环境。
- 面板提供"重播"按钮；切换槽位、替换音效后都可以立刻重播。
- 面板里试听新音效时，**动画和新音效一起放**，而不是只放声音。
- **我的决定：** 面板内的场景使用独立的状态副本，不读写当前存档。
- **交给实施方：** 每个槽位的预设状态和脚本如何构造最省事（可以复用 `src/testing/` 里的测试夹具）。

### 4. 选择与导入

- 音效库 = `src/assets/sfx/` 下所有 ogg 文件，列表可试听。
- 支持导入新文件（ogg / mp3 / wav）。导入后写入 `src/assets/sfx/`。
- **我的决定：** 导入时统一压缩为单声道、约 48 kbps 的 ogg，沿用本项目已做过的压缩参数。压缩依赖 ffmpeg，见"待用户决定"。
- 槽位可挂多个文件：面板里以列表形式增删。
- 面板提供单槽位音量倍数（默认 1），随配置一起保存。**我的决定。**

### 5. 保存与写回

- 保存按钮保存当前所有改动（可以一次改多个槽位），也支持放弃改动。
- 开发服务器插件新增一个接口，接收 `{ 槽位表, 新导入的文件 }`，校验后写 `sfxMap.ts` 和音效文件。校验：槽位键必须在清单里、文件名只能是安全字符、文件必须在 `src/assets/sfx/` 内。
- 保存后 Vite 热更新，游戏内立刻使用新音效。
- 未保存的改动在面板里有标记，关闭面板时提示（沿用卡牌编辑面板的做法）。

### 6. 安全

- 只在开发服务器存在；生产构建里不带面板组件和接口。
- 自定义请求头校验，防止其他网页跨域写本机文件。
- 文件名白名单、路径限定在 `src/assets/sfx/`，拒绝路径穿越。

### 7. 触发方式、合成音与细节（均为我的决定）

- **触发点放在哪：** 战斗内的音效挂在演出队列（`useFx` 的事件处理）上，按事件类型和原因查槽位，所以面板复现和真实游戏走同一条路径，不用在每个界面里逐个加 `playSfx`。战斗外的触发点（金币、锻造、塞牌、遗物展示等）仍在原界面里调用，但改成传槽位键。
- **合成的分裂音：** 该槽位的初始配置是"用代码合成的音效"，也可以改选为文件。选了文件就覆盖合成音；清空则回到合成音。
- **播放参数：** "只播开头 N 秒"挪进槽位配置，和音量倍数一起保存，不再由调用处传参。
- **节流：** 按槽位计，同一槽位 40 ms 内只响一次；不同槽位即使用同一个文件也各自响。
- **"未配音效"状态：** 槽位有三种：已配、未配、"有意静音"。面板提供"设为静音"，静音的槽位不再显示红点。
- **文件命名与导入：** 抛弃 `名字-序号` 的 glob 分组，配置表里写明确的文件名列表。导入的文件用原名（只保留字母、数字、连字符和下划线），重名时自动加序号，不覆盖已有文件。面板只做新增和替换，不做删除文件。音效库列出 ogg、mp3、wav。
- **预览未保存的改动：** 面板试听走一层"草稿覆盖"，不改已保存的配置，所以未保存也能听到新音效。
- **热更新：** `sfxMap.ts` 用静态引入，保存后靠 Vite 热更新生效。
- **面板入口与生产构建：** 沿用 `CardEditorView` 的做法，用 `import.meta.env.DEV` 加动态引入，生产构建里不会包含面板。

## 风险（交给实施方先核实）

- 战斗外场景的复现要用独立的局内状态。如果现有的 `useRun` 是模块级单例，就需要先把它改成可多实例，这是计划里最可能变大的一块。
- `BattleView` 依赖 `useFx` 里模块级的演出队列，面板里同时挂载多个战斗界面可能互相干扰；计划里要决定面板只挂一个、切换槽位时重置队列。
