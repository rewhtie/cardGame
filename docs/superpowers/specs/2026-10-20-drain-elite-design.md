# 精英怪设计：汲取者

## 目的

做第一只精英怪。它的机制逼玩家控制出牌数量：玩家每打出一张牌，本回合的力量和敏捷各降低 1。打得越多，后面的牌越弱，和"多出小牌堆数值"的打法对着干。

## 目标

- 做出精英「汲取者」，数据放在 [enemies.ts](../../../src/data/enemies.ts)。
- 玩家的力量和敏捷可以被减到负数，例如 -1 力量、-5 敏捷都是合法状态。
- 卡面和结算时，伤害和格挡最低为 0，不会变成负数（现有的 `fold` 已经是这个行为，需要保证不被破坏）。
- 精英节点出这只精英。

## 非目标

- 不做按层数换精英、多只精英的池子；目前精英节点只有它一只。
- 不改玩家以外的单位：只有玩家会被减力量和敏捷。
- 不定最终数值，下面的数值只是初始建议。

## 反目标

- 敌人的行动带任何随机或条件分支：意图是一条固定循环，机制只放在被动里。
- 减益在回合结束后没有恢复，变成永久削弱。
- 力量或敏捷为负数时界面出错，例如悬浮说明写成"+-3"。

## 约束

- 引擎保持纯函数，战斗由种子决定。
- 沿用状态系统：敌人的被动用"开战自带的状态"表示（见 [enemy-mechanics 设计](2026-10-19-enemy-mechanics-design.md)）。
- 精英只有一只，不与其他敌人组合。

## 机制

### 被动「汲取」

- 玩家每打出一张牌，玩家的力量 -1、敏捷 -1。回合结束时全部恢复：玩家的力量和敏捷回到这个回合开始前的值。
- 先结算这张牌，再削弱。所以刚打出的这张牌不受影响，从下一张起才变弱（我的方案）。
- 每张牌都算，包括 0 费牌，不分攻击或技能（我的方案）。药水不算。
- 汲取者已经死亡时不再触发，包括被这张牌杀死的情况（我的方案）。
- 场上有多只带「汲取」的敌人时各自生效，削弱叠加（我的方案，目前不会出现）。
- 力量和敏捷可以是负数。负力量让攻击伤害变少，负敏捷让格挡变少，结算后最低为 0。

### 汲取者本体

- 初始建议：生命 80，开战自带「汲取」1。
- 固定循环（我的方案）：攻击 8 → 格挡 12 → 攻击 14。
- 精英节点出它；事件触发的战斗不受影响。

## 引擎需要新增的能力

1. 敌人被动的新钩子：玩家出牌（结算完）之后触发。
2. 状态系统支持负层数：现有代码在加状态、收集修正时都只认层数大于 0。力量和敏捷需要允许为负；层数回到 0 时状态应当被移除。
3. 回合结束恢复：记录本回合被削弱了多少，回合结束时加回去。
4. 精英节点的出怪配置（类似怪物池和 Boss 的做法）。

## 留给实现者决定

- 上面标"我的方案"的细节如有更合适的实现，可调整，但"意图固定"、"回合结束恢复"、"可以减成负数"这三条不能动。
- 用什么记录本回合被削弱的量，例如玩家身上的一个状态。
- 负数在界面上怎么显示：状态图标的层数、悬浮说明里"+N"的写法需要处理负数。
- 新状态的图标、悬浮文案、动画。
- 单元测试怎么写，沿用现有 [enemies.test.ts](../../../src/engine/enemies.test.ts) 的风格。
